# Documentation Generation

This document describes how documentation is generated for the Radius TypeScript SDK.

## Overview

Documentation is automatically generated from source code using TypeDoc, with thin guide templates for narrative content.

```
Source Files (JSDoc comments)
       │
       ▼
    TypeDoc
       │
       ▼
docs/api/          ← Auto-generated API reference
docs/guides/       ← Thin narrative guides
```

## Generating Documentation

```bash
# Generate all documentation
pnpm generate:docs

# Generate only API reference
pnpm generate:api

# Generate only guides
pnpm generate:guides

# Validate documentation
pnpm docs:check
```

## How It Works

### API Reference (TypeDoc)

API documentation is automatically extracted from JSDoc comments in source files.

**Configuration:** `typedoc.json`

**Entry points:**
- `src/index.ts` - Main exports
- `src/server/index.ts` - Server handlers
- `src/react/index.ts` - React hooks
- `src/events/index.ts` - Event utilities
- `src/wagmi/index.ts` - wagmi integration
- `src/chains/index.ts` - Chain definitions

### Guides (Templates)

Narrative guides are generated from templates in `scripts/generate-guides.ts`.
These are thin files that link to the auto-generated API reference.

## Adding Documentation

### To Document a New Export

1. Add JSDoc comments to your source file:

```typescript
/**
 * Brief description of the function.
 *
 * @param param - Description of the parameter
 * @returns Description of the return value
 *
 * @example
 * ```typescript
 * const result = myFunction('input');
 * ```
 */
export function myFunction(param: string): number {
  // ...
}
```

2. Re-generate documentation:

```bash
pnpm generate:docs
```

### To Add a New Guide

1. Edit `scripts/generate-guides.ts`
2. Add a new guide constant
3. Add it to the `guides` array
4. Re-generate: `pnpm generate:guides`

## CI Integration

Documentation should be checked in CI:

```yaml
# .github/workflows/docs.yml
jobs:
  docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
      - run: pnpm install
      - run: pnpm generate:docs
      - name: Check for changes
        run: |
          git diff --exit-code docs/ || {
            echo "Documentation out of sync. Run 'pnpm generate:docs' and commit."
            exit 1
          }
```

## Validation

The `docs:check` script validates documentation for common issues:

- References to removed V1 signer types
- References to old package names
- Missing required files

Migration guides are excluded from stale pattern checks since they intentionally reference old APIs.

## External Docs Site

The docs team ingests files from this directory. Format changes should be communicated to ensure compatibility.

**Expected structure:**
- `docs/api/` - TypeDoc markdown output
- `docs/guides/` - MDX guide files

## Troubleshooting

### TypeDoc Warnings

TypeDoc may warn about:
- `@param` with unused names - Update JSDoc to use correct parameter names
- Referenced types not included - Either export the type or mark it `@internal`

### Validation Failures

If `docs:check` fails:
1. Check if you're referencing removed code
2. Update the code or add to validation exceptions
3. Re-generate and re-validate

## Migration from V1

The previous documentation system (`scripts/generate-docs.ts`) used hardcoded MDX templates. It has been archived to `archive/generate-docs-v1.ts`.

The new system:
- Extracts API docs from JSDoc (never drifts)
- Uses thin guide templates (easy to maintain)
- Validates for common issues (catches problems early)
